导出机场配置时删掉订阅链接就能公开吗？还要检查节点凭据

闪电云2026-11-20— 次阅读
订阅与配置

准备把机场客户端配置发给客服或公开求助时，删掉一条订阅 URL 并不等于整份文件已经脱敏。订阅更新后，配置里可能已经有可用于连接的节点字段。先确定用途，再制作副本检查，别把自用备份直接当成公开样例。

为什么删除订阅地址还不够

官方配置文档给出了不同层面的字段：mihomo 的 Shadowsocks 节点包含 password；sing-box 的 VLESS 出站包含 uuid 用户标识；mihomo 的 HTTP 类型 proxy-providers 则有远程 url。Shadowsocks 字段、VLESS 字段、provider 配置。

这些是格式可能携带的内容，不表示你的文件一定采用全部字段，也不能把所有 UUID 都当作同一种密码。需要按具体协议和客户端结构检查；删除上游订阅入口，不会必然删除已展开节点中的连接凭据。

示意图：删除订阅地址并不会自动移除配置中其他凭据；图中没有真实链接或密码。

自用备份与公开求助分成两份

用途 应保存什么 不应混淆什么
自己恢复客户端 按客户端说明保留必要内容，存入受控位置 脱敏后文件可能已无法连接
发给正式客服 只提供定位本次问题所需的最小字段 客服身份不代表需要整份凭据
公开讨论格式问题 人工重建最小样例，使用明显占位值 自用原件不能直接公开

备份前先确认客户端的导出范围：当前配置、全部配置、订阅来源和数据库可能不是同一对象。对需要保留凭据的自用备份，使用自己可控制的存储与访问权限；如采用加密备份，妥善保管恢复方式，并在本机验证能否读取。加密文件也不应随意公开。

制作脱敏副本的五步检查

  1. 在本机复制一份文件，保留原件不动，明确标为“公开排障副本”。
  2. 先删去与问题无关的节点、provider、规则和账号资料，只保留最小复现结构。
  3. 逐项检查链接及查询参数、password、用于认证的用户标识、请求头里的认证值，以及本地路径和个人域名；字段名只是检查线索，不是完整自动脱敏规则。
  4. 检查嵌套项、注释、导出目录的其他文件及截图；删除一处后搜索是否还有同一真实值。
  5. 重新阅读全部副本，确认没有实际节点访问凭据，再交给预定对象。

不要把含真实配置的文件上传到陌生“在线脱敏”或“配置转换”网站来完成这项检查。排障讨论只要说明结构问题，就优先用不存在的占位内容；不要从官方文档复制示例后声称它是自己的实测节点。

已经发出去，先按暴露对象处理

记录分享范围和文件版本，通过服务正式入口询问对应凭据能否重置。账号密码、订阅地址和节点认证信息可能是不同对象；不能假定改一个就撤销全部。保留处理记录，更新自己的客户端后再做小型任务验收，避免持续使用已经替换的配置。

备份与分享各自怎样验收

自用备份的标准是能在自己的受控环境恢复；公开副本的标准是能够解释问题且没有可用的私人凭据。二者不能用同一份文件凑合。机场推荐中的订阅安全，也应覆盖导出、备份和求助这几个经常被忽略的步骤。

  • sing-box：VLESS 出站字段
